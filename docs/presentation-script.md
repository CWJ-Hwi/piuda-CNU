# 피우다 2.0 8분 발표 시나리오

발표 제어실은 실수를 줄이기 위해 **기본 상태 → 식사 지연 → 장시간 비움** 세 장면만 제공한다. 앱을 다시 실행하면 항상 기본 상태에서 시작한다.

## 발표 화면

| 화면 | 주소 | 역할 |
| --- | --- | --- |
| 제어실 | `http://192.168.4.1:8080/demo` | 세 장면 전환 |
| 사용자 | Pi의 `http://127.0.0.1:8080/?kiosk=1` | 일정·점수·AI·위험 팝업 |
| 보호자 | `http://192.168.4.1:8080/caregiver` | PIN `3017`, 근거·센서·위험 팝업 |

## 발표 대본

### 00:00–00:45 · 문제와 기본 상태

> 피우다는 초기 치매 환자와 경증 장애인의 일상 수행을 돕는 Raspberry Pi 기반 자립생활지원 시스템입니다. 카메라로 생활을 촬영하지 않고 일정 수행 정보와 PIR, Wi-Fi CSI 생활 신호를 사용합니다. 지금은 최근 움직임과 일정이 정상인 100점 안심 상태입니다. 이 점수는 의료 진단이 아니라 보호자가 확인 순서를 정하는 보조 정보입니다.

### 00:45–01:30 · 로컬 구조

> Raspberry Pi가 PIUDA-CNU 2.4기가헤르츠 핫스팟과 192.168.4.1 고정 주소를 만들고 두 ESP32가 자동 연결됩니다. 센서는 PIR과 Wi-Fi CSI 요약을 보내고 거실 보드는 비접촉 온도도 전송합니다. Flask 서버가 일정과 센서 신호를 점수화해 SQLite에 저장하며 사용자와 보호자 화면은 2초마다 같은 API를 조회합니다. 인터넷 연결 없이도 핵심 기능이 동작합니다.

### 01:30–02:30 · 반복 일정

> 보호자는 식사, 복약, 외출 같은 일정을 등록하고 월요일부터 일요일까지 반복 요일을 선택합니다. 서버는 요일을 비트마스크로 저장하고 오늘 날짜와 시간을 결합해 체크리스트를 만듭니다. 같은 일정이 중복 생성되지 않도록 일정 ID와 예정 시각을 유일키로 사용합니다. 사용자가 완료 버튼을 누르면 완료 시각을 저장하고 점수를 즉시 다시 계산합니다.

### 02:30–03:30 · 보호자 화면과 맞춤 AI

> 보호자 화면에는 건강 점수, 일정, 감점 근거, 센서 상태와 알림이 모입니다. 보호자는 사용자의 연령과 성별을 선택하고 질병, 장애, 돌봄 참고 정보와 선호하는 대화 방식을 문장으로 기록할 수 있습니다. 이 정보는 인증된 보호자 화면과 내부 LLM 입력에서만 사용하며 공개 프로필 API에는 노출하지 않습니다. 모델은 표현 난이도와 생활 제안에만 참고하고 의료 진단이나 복약 변경은 하지 않도록 제한합니다.

### 03:30–04:30 · 식사 지연

1. 제어실에서 `식사 지연`을 누른다.
2. 사용자 화면의 `60점 · 주의`와 점심 식사 미수행을 보여 준다.
3. 보호자 화면의 두 감점 근거를 가리킨다.

> 점심 식사 예정 시간이 지났고 이후 활동도 확인되지 않은 장면입니다. 식사 지연 15점과 예정 시간 이후 활동 미감지 25점을 합쳐 100점에서 60점으로 낮춥니다. 결과만 보여 주는 것이 아니라 어떤 규칙이 몇 점을 낮췄는지 보호자 화면에 함께 표시합니다.

### 04:30–06:00 · 장시간 비움과 양쪽 위험 팝업

1. 사용자와 보호자 화면을 모두 전면에 둔다.
2. 제어실에서 `장시간 비움`을 누른다.
3. 2초 안에 사용자 화면의 위험 팝업과 보호자 화면의 위험 팝업을 함께 보여 준다.
4. 보호자 팝업의 `확인했습니다`를 눌러 처리 시각이 기록되는 것을 보여 준다.

> PIR과 Wi-Fi CSI 생활 신호가 4시간 동안 확인되지 않은 장면입니다. 장시간 PIR 미감지 30점과 통합 생활 신호 부재 40점을 적용해 30점 위험 상태가 됩니다. 사용자 화면에는 보호자에게 알렸다는 큰 팝업이 뜨고, 보호자 화면에는 같은 데이터에서 생성된 위험 알림이 소리와 함께 표시됩니다. 보호자가 확인하면 처리 시각이 저장되어 미확인 알림 수에서 빠집니다.

### 06:00–07:00 · 로컬 음성 AI

> 사용자는 USB 마이크로 질문합니다. whisper.cpp가 Raspberry Pi 안에서 한국어 음성을 글로 바꾸고, 한국어 특화 HyperCLOVA X SEED 모델이 일정, 점수, 최근 대화와 보호자가 등록한 정보를 참고해 답합니다. 답변은 Supertonic 3 음성으로 재생합니다. 긴급 표현과 일정 질문은 모델을 기다리지 않고 규칙으로 즉시 답하며 모델 실패 시에도 안전 문구로 폴백합니다.

### 07:00–08:00 · 기본 상태 복귀와 결론

1. 제어실에서 `기본 상태`를 누른다.
2. 사용자와 보호자 화면이 100점 안심으로 돌아오고 열린 위험 팝업이 닫히는 것을 확인한다.

> 기본 상태로 전환하면 제어실이 일정, 센서, 점수와 알림을 정해진 초기 장면으로 되돌립니다. 피우다는 AI에게 위험 판단을 맡기지 않습니다. 일정과 비접촉 센서 신호는 설명 가능한 규칙으로 판단하고 AI는 사용자가 이해하기 쉬운 생활 안내를 담당합니다. 카메라 없이 필요한 신호만 수집하고 위험할 때 사용자와 보호자 양쪽에 분명하게 알리는 것이 핵심입니다. 감사합니다.

## 구현 근거

| 기능 | 구현 |
| --- | --- |
| 3개 데모 장면 | `piuda/demo.py`의 `DEMO_SCENARIOS`, `trigger_demo_scenario()` |
| 부팅 기본 상태 | `piuda/cli.py`가 데모 모드 실행 때 `reset_demo()` 호출 |
| 식사 지연 | 점심 occurrence를 `missed`로 바꾸고 60점 주의 override 저장 |
| 장시간 비움 | 4시간 전 PIR 기록, 30점 위험 override, danger alert를 한 트랜잭션에 저장 |
| 사용자 위험 팝업 | `piuda/static/app.js`의 `syncUserDangerPrompt()` |
| 보호자 위험 팝업 | `notifyNewCaregiverAlert()`와 alerts 확인 API |
| 화면 동기화 | 사용자·보호자·제어실 2초 `no-store` 폴링 |
| 실제 점수 엔진 | `piuda/risk.py`의 일정·무활동·CSI·센서 연결 규칙 |
| 보호자 인증 | PIN 해시, 해시된 bearer token, 로그아웃 시 토큰 폐기 |
| 맞춤 AI | 프로필 맥락을 데이터로 구분해 Ollama에 전달하고 의료 판단 금지 |

## 발표 전 체크리스트

- [ ] Pi 시간이 현재 날짜와 `Asia/Seoul` 시간대로 맞다.
- [ ] Pi를 다시 실행한 뒤 제어실의 현재 장면이 `기본 상태`, 100점이다.
- [ ] `/demo`에 카드가 정확히 3개만 보인다.
- [ ] 보호자 화면을 PIN `3017`로 로그인하고 한 번 터치해 알림음을 활성화한다.
- [ ] `식사 지연`에서 60점·주의·점심 미수행을 확인한다.
- [ ] `장시간 비움`에서 30점·위험과 사용자·보호자 양쪽 팝업을 확인한다.
- [ ] `기본 상태`로 돌아갈 때 팝업이 닫히고 100점으로 복귀한다.
- [ ] ESP32 2대의 최근 신호와 Peak Delta가 보호자 화면에서 갱신된다.
- [ ] USB 마이크, STT, Ollama, Supertonic TTS를 한 번씩 확인한다.

## 실패 대비

| 문제 | 즉시 대응 |
| --- | --- |
| 장면 반영이 늦음 | 2초 기다린 뒤 해당 화면을 한 번 새로고침 |
| 보호자 팝업이 안 뜸 | 보호자 로그인과 화면 포커스를 확인하고 `장시간 비움`을 다시 실행 |
| 알림음이 안 남 | 보호자 화면을 한 번 터치한 뒤 시각적 팝업으로 계속 설명 |
| AI 응답이 늦음 | 중복 전송하지 않고 규칙 기반 일정·안전 폴백을 설명 |
| 서버 응답 없음 | `http://127.0.0.1:8080/api/v1/health` 확인 후 앱을 한 번 재실행 |
